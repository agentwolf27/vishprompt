# VishPrompt UI/UX review and plan — 2026-10-23

Read-only review. Code is cited from `dev` at e181842. The research doc and the proposal in PLAN.md come from `docs/pastely-confirmed`; `feature/smart-paste` has no UI changes yet. Web sources were read on 2026-10-23 and are listed at the end. Nothing in the VishPrompt repo was edited.

## One-screen summary

- **The surfaces.** There are five: the HUD (listening, transcribing, compiling, ready, inserted, failed), a menu bar window, a setup window, a destinations window, and nothing else. **No history, vocabulary or providers settings screen exists.** Providers can only be changed inside Setup (`OnboardingView.swift:185`).
- **What is strong.**
  - The non-activating panel keeps the caret where it is (`HUDPanel.swift:36-38`).
  - The preview is the right safety valve for agent prompts.
  - The paste test uses the real insertion path.
  - Copy is mostly plain English and honest about speed.
- **The biggest problem: text gets lost.** "Focus moved", "Preview expired" and provider failures each show for 1–2.5 s and then vanish. The text is in SQLite, but no screen can show it (`DictationController.swift:414,539,567`). The plan promised that the error state copies the raw transcript to the clipboard (plan.html, "The HUD"). Only the secure-input path does that.
- **Second: the preview hides what you are about to send.**
  - The text is cut at 5 lines (`HUDView.swift:113`). Compiled Claude Code prompts are longer, so you press Return on text you cannot fully see.
  - Tab blanks the preview while it recompiles (`DictationController.swift:488`), which takes 6–10 s on the subscription.
  - Tab only cycles forward, and nothing is cached, so going back one level costs three recompiles.
- **Third: the HUD is silent to VoiceOver.**
  - The only accessibility label in the app is on the menu bar icon (`VisprflowApp.swift:29`).
  - The panel can never become key, so VoiceOver cannot reach the preview at all. It needs announcements.
  - There is no Reduce Motion handling.
  - Key hints use `.tertiary` caption2 text on material (`HUDView.swift:74-76,107-109`), which is low contrast.
- **Fourth: settings break macOS conventions.**
  - ⌘, opens a window titled "VishPrompt Destinations" (`MenuBarView.swift:43-46`, `SetupWindowController.swift:50`).
  - Changes need a Save button, and switching rows silently throws away unsaved edits (`DestinationSettingsView.swift:25,105`).
  - The menu bar extra is a window, where the HIG says to use a menu.
- **For the two new features,** the HUD needs a visible **mode chip** (Dictate / Paste / Fix) and a **source line** saying what went in and what left the Mac. Specs are in §3.
- **Top 5 changes.**
  1. Never lose text.
  2. Show the full, scrollable preview, and cache each level.
  3. VoiceOver announcements and labels, plus Reduce Motion.
  4. A mode chip and "what was sent" line in the HUD.
  5. A real Settings window, plus the History window that doubles as the privacy ledger.

## 3. Specs for the two features being built now

**Shared HUD model.**
- **Header** = mode chip · destination chip · provider chip · key hints. Mode chips:
  - `Dictate` (mic.fill)
  - `Paste` (doc.on.clipboard)
  - `Fix` (ladybug)

  The chip has a text label, not only an icon and colour [HIG-A11y]. VoiceOver announces it on key-down: "Paste mode, into Slack".
- **Source line** (new): one line above the key hints saying what went in and what leaves. Example: "From clipboard: CSV, 14 rows · sent to Claude subscription". Or: "Stays on this Mac".
- **Every ending that does not insert** puts the text on the clipboard and says so (finding 1).

### 3a. Smart Paste — hold fn+V, say how; silence = the destination's default

| State | HUD shows | Keys / behaviour |
|---|---|---|
| Key-down, clip OK | `Paste` → `Slack`; clip summary "Text · 3 lines, copied 20 s ago". Ages are coarse: just now, N s up to 60 s, N min, then "over an hour" | Hold and speak. Release with no speech applies the default |
| Listening | Live words as today; hint "say how to paste it — or release for Slack's default" | esc cancels |
| Silence, default | "Slack default: light cleanup" in the header; if the default is verbatim (Shell) it pastes immediately and shows "Pasted as-is (Shell)" | Shell never transforms |
| Rewriting | "Rewriting for Slack · on this Mac". Show the old clip dimmed, not a blank | esc |
| Preview (always shown for Paste in v1: the clip isn't the user's own words) | Result, plus "You said: 'as bullet points'" so a mishearing is visible before it lands; the source line | ⏎ paste · ⇥ format · R redo · ⌥⏎ paste the original · esc. The clipboard is untouched until ⏎, as in Pastely [PA] |
| Empty clipboard | **Named state** "Clipboard is empty" · cause "nothing copied since login, or the last copy expired" · action "Copy something, then hold fn+V" | Auto-hides at 3 s |
| Concealed clip | "Clipboard holds a password-manager item — VishPrompt doesn't read those. Use ⌘V." | Never read |
| Image-only clip, non-agent destination | Goes to the OCR path in §3b, with the chip `Paste · text from image` | — |
| Clip too long | "Clip is 48,213 characters; the first 12,000 will be rewritten. ⏎ continue · ⌥⏎ paste original". Character counts are exact, so print them exactly | — |
| Provider failed | "Couldn't reach Claude (offline). ⏎ pastes the clip unchanged · esc" | Falls back to the clip, never to blank |
| Pasted | "Pasted into Slack · ⌘Z undoes"; the clipboard is restored to the original clip | Always the paste strategy, so one ⌘Z undoes it (typing would leave many undo steps). The HIG asks that undo be predictable [HIG-Undo] |

### 3b. Screenshot → "fix this" in Claude Code (on-device OCR, secrets removed, structured prompt)

| State | HUD shows | Notes |
|---|---|---|
| Key-down, image on clipboard ≤2 min old | `Fix` → `Claude Code`; a 32 pt thumbnail; "Screenshot copied 40 s ago — will be read on this Mac" | The chip lights up the way superwhisper's context indicator does [SW1] |
| Image older than 2 min | "Older screenshot ignored (14 min)"; say "use the screenshot" to include it | Prevents fixing last hour's error |
| "fix this" with no image | The prompt is built from your words only; the source line says "No screenshot on the clipboard — used your words only" | Honest, not an error |
| OCR running | Step list in the compiling state: "Reading screenshot on this Mac ✓ → Checking for secrets ✓ → Writing prompt…" | Show a step only if it takes >300 ms, so it never flickers. Under Reduce Motion, a static "…" replaces the spinner |
| **Nothing found** | **Named state** "No text found in the screenshot" · cause "it looks like a picture, or the text is very small" · action "⏎ send your words without it · R redo with a bigger screenshot (⌘⇧⌃4) · esc" | Never fails silently with an empty "Error:" block |
| Some text hard to read | "Some lines were hard to read — check the error text" (no percentage). Low-confidence lines are underlined dotted in the preview | Vision's per-line confidence is not a calibrated probability, so showing "87%" would be fake precision |
| **Secrets removed** | Footer, info tint (not warning): "(shield.lefthalf.filled) Removed before sending: 1 AWS key (…F3QA), 1 bearer token. They appear as [AWS key removed]." | Show only the last 4 characters so the user can recognise the secret without it being redisplayed. Secrets are never put back automatically; the user can still type them in. History records the types, not the values |
| No secrets | Nothing in the HUD; History says "checked: none found" | Keeps the HUD quiet |
| Preview | Sections with sources: **Goal** (your words) · **Error** (from screenshot, 23 lines, folded to 6 with "+17") · **Where** (repo, branch, files you named) · **Verify**. Source line: "Sent: your words + 23 lines of screenshot text → Claude subscription. The image stays on this Mac" | ⏎ insert · ⇥ level · ⌥⏎ insert without screenshot text · R · esc |
| Inserted | "Inserted into Claude Code — not sent. Review, then press Return in Claude Code" | Auto-submit is forced off for Fix. Terminals have no ⌘Z, so the HUD should name the line-clear key; that key is UNVERIFIED for Claude Code's multi-line input and needs testing. History: "Copy again" |

## 4. Phased plan

**This week — quick wins.** All effort S. They touch only `UI/`, `DictationController` messages and error strings.

| Item | Outcome | Verify |
|---|---|---|
| Q1 Never lose text (findings 1, 8, 29) | Every ending that doesn't insert leaves the text on the clipboard and says so | New `HUDCopyTests`: each `.failed` message names a cause and an action, and the clipboard holds the text — `make test` |
| Q2 Preview you can trust (2, 4, 5) | Full scrollable preview; per-level cache; ⇧Tab; R shown in the hints | `grep -q ScrollView Visprflow/UI/HUD/HUDView.swift`; manual: a 20-line prompt can be read end to end; Tab back to the first level is instant |
| Q3 VoiceOver + Reduce Motion + contrast (3, 11, 16) | VoiceOver announces each state and the preview's first sentence | `grep -q announcementRequested Visprflow/Core/Pipeline/DictationController.swift`; manual pass with VoiceOver and Accessibility Inspector's audit |
| Q4 Provider and escalation chip (9, 10) | You always see where text was processed | `grep -q providerLabel Visprflow/UI/HUD/HUDView.swift` |
| Q5 Copy fixes (6, 7, 17, 19–22, 24, 25) | No jargon or raw errors; permission count correct | `grep -q "Two permissions" Visprflow/UI/Onboarding/OnboardingView.swift` |
| Q6 Destinations autosave (23) | Edits survive switching rows | Manual: edit, switch rows, switch back, and the edit is still there |

**Then — larger items.**

| Item | Outcome | Verify |
|---|---|---|
| L1 Settings + menu (13, 14, 15, 18, 27) — M | A `Settings` scene with General · Providers · Destinations · Vocabulary · Privacy; a `.menu` extra with Last dictation, History and Pause; 3-step setup | `grep -qF "menuBarExtraStyle(.menu)" Visprflow/App/VisprflowApp.swift`; ⌘, opens the last pane |
| L2 History = privacy ledger (28) — M–L, pairs with research R2 | Each row: what you said → exactly what was sent, or "Nothing left this Mac" → result → stage timings. Copy, paste again, re-run at a level, retry a failed one | `grep -rq HistoryView Visprflow/UI` (already a proposed PLAN line). Timings: below 1 s, two significant figures ("210 ms"); above that, one decimal ("6.4 s"); single runs only, no error bars; medians only with n shown |
| L3 Mode-chip HUD for Paste and Fix (§3) — M, built with feature/smart-paste | Mode, destination and provider chips; the source line; all §3 states | New `HUDStateTests` for `.emptyClipboard`, `.noTextInImage`, `.secretsRemoved` — `make test`; golden cases for both features — `make eval` |

Sequencing: Q1–Q3 first, because they stop data loss and exclusion. L3 lands with the feature branch. L2 then makes the "what was sent" claim visible.
